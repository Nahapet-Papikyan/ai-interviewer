# Current architecture

This document maps the repository as of 2026-08-19. Runtime is Next.js App Router. There is no `pages/` router. There is no `prisma/migrations/` directory.

## Dependency versions

See `00_EXECUTIVE_SUMMARY.md` for lockfile versions.

Important configuration:

- `next.config.ts`: `transpilePackages: ["@openai/agents"]`, `serverExternalPackages: ["@prisma/client", "prisma"]`.
- `tsconfig.json`: `strict: true`, paths `@/*` → `./src/*`.
- `vercel.json`: framework `nextjs` only.
- Prisma: PostgreSQL, client binary targets `native`, `debian-openssl-3.0.x`, `rhel-openssl-3.0.x`.
- Seed: `tsx prisma/seed.ts`. Seed **deletes all companies/interviews** then recreates three fixtures.

## High-level data flow

```text
Admin UI / REST ingest / MCP / public assessment
        │
        ▼
createInterviewInvitation / prisma create
        │
        ▼
Interview.publicTokenHash  ←  SHA-256(opaque token)
        │
        ▼
GET /i/{token}  →  OPENED  →  InterviewClient (browser)
        │
        ├─ POST /api/interviews/session  (consent, history, facts, complete)
        └─ POST /api/realtime/token
                │
                ├─ buildInterviewerInstructions (v2 prompt + runtime state)
                └─ POST api.openai.com/v1/realtime/client_secrets
                        │
                        ▼
Browser RealtimeSession (WebRTC) ↔ gpt-realtime-2.1
        │
        ├─ history_updated → planTranscriptUpsert → InterviewMessage
        ├─ tools → InterviewFact / Interview.state
        └─ complete → InterviewStatus.COMPLETED
                │
                ▼ (manual admin POST /api/analysis)
Responses API Structured Outputs → Process / Opportunity / InterviewAnalysis
                │
                ▼
Admin dashboard + JSON/CSV export
```

## Authentication and invitation

1. Admin password compared in `checkAdminPassword` (`src/lib/auth-token.ts`).
2. Session cookie `ai_admin` = `admin.<expires>.<hmac>` (7 days).
3. Middleware matcher covers HTML admin paths only, not `/api/*`.
4. Public interview token: 24 random bytes, base64url, stored as SHA-256 hex (`src/lib/tokens.ts`).
5. Admin `createInvitation` redirects to `/interviews/{id}?token={plaintext}` so the operator can copy the URL once.

## OpenAI integrations

| Use | Model default | Code |
| --- | --- | --- |
| Voice interview | `gpt-realtime-2.1` | `realtimeModel()`, ephemeral `client_secrets` |
| Input transcription | `gpt-live-transcribe` | session `audio.input.transcription` |
| Output voice | `sage` | `realtimeVoice()` / env |
| Post-interview analysis | `gpt-5.6-terra` | `client.responses.parse` + Zod |
| Text interview fallback | **none** | missing |

Browser tools (`record_process_candidate`, `record_key_fact`, `mark_interview_complete`) execute in the browser and POST to `/api/interviews/session`. That matches `Docs/01_IMPLEMENTATION.md` (privileged work stays on the server). The session endpoint is authorized only by possession of the invitation token.

## What is not present

- No Prisma migrate history.
- No Redis / durable rate limiter.
- No analysis job queue.
- No audio storage (intentional).
- No native-name columns (`firstNameHy`, `companyNameHy`).
- No unique constraint on `(interviewId, providerEventId)`.
- No Responses API live-interview path.
- No `proxy.ts` (Next.js 16 convention).
- No tests under `src/lib/openai/`.
- No request body size limits beyond Next defaults.
- No `OpenAI-Safety-Identifier` header on client-secret minting.
